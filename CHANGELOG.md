# Changelog

## 0.3.0 — 2026-08-21

- Send the `x-tr-client` client-observed reliability telemetry header (contract v1, header channel only). Content-free by construction — closed enums and bounded integers — never sent to custom base URLs or on control-plane calls, and disabled by `Telemetry: false` (new `Options.Telemetry *bool`), `TRUSTEDROUTER_TELEMETRY=0`, or `DO_NOT_TRACK=1`. Opting out does not change the User-Agent.
- **User-Agent format changed** (visible on the wire). The trailing OS token is gone: the header is now `trusted-router-go/SEMVER go/RUNTIME` (for example `trusted-router-go/0.3.0 go/go1.23.4`) where it was `trusted-router-go/SEMVER go/RUNTIME GOOS` (`trusted-router-go/0.2.0 go/go1.23.4 darwin`). The old shape did not parse under the telemetry contract's §3.1 grammar, which the enclave derives the SDK identity from; anything matching on the old shape needs updating. A runtime token outside the §5.1 grammar is omitted rather than sent.
- Harden the `x-tr-client` channel after the cross-SDK independent review round: proxy failures classify as `proxy_error` ahead of the DNS/refused checks, so a broken local proxy never counts against TrustedRouter's availability; TLS handshake timeouts classify as `connect_timeout`; `ErrSchemeMismatch` and http2 stream resets are classified instead of reported as `unknown`; classification walks a bounded six-link error chain instead of `errors.Is`/`errors.As`, so a caller-injected error with a cyclic `Unwrap` can no longer hang the engine; every recorder callback is recover-guarded, so a hostile error value from an injected `http.Client` costs a telemetry record, never the request; telemetry names hosts from its own fixed list rather than the mutable `AliasAPIBaseURLs`; attempt numbers stay honest across a dropped record; the header name is reserved on every path (caller-supplied values are stripped, including on opt-out, custom bases, and control-plane calls); an out-of-vocabulary previous outcome maps to `po=none;pc=none`; recorder state is bounded.
- Fail over to the alias domains. New `AliasAPIBaseURLs` (`api.allyrouter.com`, `api.uptimerouter.com`) are exact aliases of the primary on separate domains and DNS providers; the client walks them after `DefaultAPIBaseURL` on connection failures and on 502/503/504, while a 500 is retried on the same host. Previously the candidate list held one entry and the request loop never advanced. Aliases apply only to the default base URL; a custom `Options.BaseURL` is never rewritten.
- Honor the gateway's `x-should-retry` label, so a 5xx the gateway marks as not-to-be-re-sent is not re-sent; parse `retry-after-ms` (wins over `Retry-After` when both are present). `Options.RegionalFailover` now governs only where a retry goes: a pinned client (`RegionalFailover: false`) still retries on its own host, where it previously stopped retrying 502/503/504 and transport failures altogether.
- Stream opens gain the buffered path's full retry semantics — candidate walk, `x-should-retry`, `Retry-After`, and pinned in-place retries — instead of the old separate loop. Internally the package was restructured along the cross-SDK layer stack (one engine loop in `transport.go`); no public API or import path changed.
- Retry only when replay is safe. A transport error may occur after a server accepted the body, and a retryable response (429, 5xx, or an `x-should-retry: true` label) means one may have processed it, so a retry or host move in either case now requires a replay-safe method (GET, HEAD, OPTIONS, TRACE) or an idempotency key. The high-level endpoints mint one key per logical call and keep retrying with it; a `Request`/`RawRequest` with any other method and no `CallOptions.IdempotencyKey` is no longer re-sent after a transport error or a retryable response. Generated keys stay unique even if `rand.Reader` fails.
- Bound `Retry-After` with the new `MaxRetryAfterSeconds` (60 s), matching the other SDKs. `strconv.ParseFloat` accepts `inf` and hex floats and the float-to-`time.Duration` conversion saturates, so `Retry-After: inf` produced a 292-year timer with no error to notice.
- Attestation fails closed on a policy that pins no image identity. New `AttestationPolicy.PinsImageIdentity()`; both `PolicyFromTrustRelease` and `VerifyGatewayAttestation` now refuse such a policy, where an empty accepted set previously skipped both image checks. Accept the published rollout pins: `TrustRelease.AcceptedImageReferences`/`AcceptedImageDigests` and `AttestationPolicy.ExpectedImageReferences`/`ExpectedImageDigests` permit a published transition set during staged rollouts.
- Never follow redirects. API requests hand the 3xx back to the retry engine instead of replaying prompt bodies and SDK headers to a `Location` on another origin; a supplied `http.Client` is shallow-cloned with only `CheckRedirect` overridden, never mutated. Standalone trust-release, JWKS, and OAuth metadata retrieval is credential-free: a fresh private client when none is supplied, never `http.DefaultClient`, no redirects, the supplied cookie jar ignored, credential-shaped default headers stripped. An empty `APIKey` override really suppresses `Authorization` (notably for OAuth). A custom `RoundTripper` remains an explicit caller-owned boundary that runs after the SDK's final header scrub.
- SSE streams fail loudly. Chat and Responses streams that end before `[DONE]` or their terminal event now yield `SSE stream ended before a terminal event`, and a malformed JSON data frame yields `invalid SSE JSON` instead of being skipped. Chat streams additionally reject a non-object data frame (`chat SSE data must be a JSON object`), which 0.2.0 silently skipped, and surface an in-stream `error` payload as an error. Responses streams keep delivering non-object JSON frames as `{"event", "data"}`, as before.
- `CollectCompletion` reconstructs every indexed choice from streamed chunks — previously it read only `Choices[0]` — and preserves the streamed message-, choice-, and completion-level extra fields (reasoning, logprobs, and other provider metadata), tool calls by index, and usage in the rebuilt `ChatCompletion`.
- Bound and harden the transport-error message. The typed SDK error is now capped at 2048 bytes in total (prefix included) and cuts on a rune boundary, so one pathological transport error value cannot balloon or mangle it. Flattening a caller-injected error value can also no longer take the process down: rendering still goes through fmt with the same `%s` verb as before — so an error's own `fmt.Formatter` keeps rendering, and redacting, exactly as it did — and a recover guard now covers the one shape fmt re-panics on, an `Error()` that panics with a value whose `Error()` panics in turn, which reaches the SDK unwrapped on the mid-stream body path. A plainly panicking `Error()` was already survivable through fmt and still renders fmt's `%!s(PANIC=...)` marker, now bounded.
- Add `SECURITY.md` (GitHub private vulnerability reporting, acknowledgement within 72 hours, no email intake) and `CODEOWNERS`. Pull requests are now gated by the cross-SDK conformance harness in addition to gofmt, go vet, `go mod tidy -diff`, `go test -race`, and staticcheck.
